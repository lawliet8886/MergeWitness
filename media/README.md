judge video. Publication receipts and exact artifact hashes are retained in
`submission/LABLAB_SUBMISSION.md`.
Its SHA-256 is `954ec9d70b26a7c32a8d7503a053ba57c8910ffcdd4717062b5ae3091b11110f`
(10,642,878 bytes); a full FFmpeg decode passed. It combines a continuous browser
recording, measured Sulafat narration, sentence-aligned captions, and labeled
screenshots from three genuine IBM Bob IDE tasks. The browser actions include a
fresh four-snapshot comparison, evidence-tab navigation, and a fresh repaired
candidate run. The video identifies the independent audit additions as such;

The refreshed capture uses the version with worker timeouts and recovery. The
actual repair result panel is enlarged from 01:39.5 to 01:49.8 and again from 02:17

To reproduce it, run the Vite server from `web/`, then run
`python media/capture_live_demo.py`, `python media/review_narration.py`,
`python media/align_final_captions.py`, and
`python media/build_continuous_video.py` from the repository root. The raw
browser recording and action manifest stay under ignored `.video-capture/`.

## Recording acceptance

Validate transitions against audio-derived word timings and frames extracted from
the final MP4; the capture script or action manifest alone does not prove sync.
Check all captions for clipping, full decode, stream start/duration, and the actual
public download hash after upload. Offline speech recognition supports content
intelligibility checks but is not a human perceptual listening assessment.

The earlier 96-second edit was built from `capture_ui_actions.py`,
`build_final_video.py`, `build_captions.py`, `narration.txt`, and
`narration_sulafat.wav`. Its public URL and SHA-256 are retained as a historical
readback in `submission/LABLAB_SUBMISSION.md`. These scripts and source files
remain for provenance, but the replacement uses the continuous capture above.
